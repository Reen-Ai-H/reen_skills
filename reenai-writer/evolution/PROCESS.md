# 养一个自己的写作风格 Skill

这份文档记录 reenai-writer 是怎么做出来、怎么一点点调准的。写给以后维护它的自己，也写给想做一份自己版本的人。

## 起点

一开始用的是别人的风格 Skill（数字生命卡兹克的 khazix-writer）。它写得很完整，但用下来有两个问题。

第一，写出来是别人的声音。口头禅、开头套路、固定结尾都是别人的，越像原作者就越不像我。

第二，硬指标会把稿子拧变形。四千到八千字的下限、每篇至少八个口语词、必须有文化升华、每次写完输出四层质检报告，材料不够的时候，模型就只能灌水。

所以留下了它好的部分（讲人话、不编经历、具体工具名、标点禁令），其余按自己的反馈重新长。

## 结构，引擎和声音分开

```
SKILL.md      引擎，怎么写、怎么改、怎么迭代。谁用都一样
references/   通用方法，各平台形式、配图流程
voice/        声音，只属于一个人
  profile.md    风格画像，写作前读
  samples/      样本
  checks.txt    自检词表
evolution/    迭代记录，写作时不读
scripts/      自检脚本，词表从 voice/checks.txt 读
```

这样分有两个好处。写作时模型只读跟下笔有关的东西，不会被一堆出处说明和历史记录带得畏手畏脚。分享时把 `voice/` 换掉，就是另一个人的 Skill。

## 冷启动，手里没几篇文章时

1. **做一次小访谈。** 你是谁，写给谁，常写什么，最喜欢和最讨厌的文章各一篇，自己说话的口头禅。十五分钟够了。
2. **做一次亲改对照。** 让 AI 起草一篇你本来就想写的东西，你自己动手改到满意，把改前改后都留下来。这是最值钱的材料，一次亲改胜过十条抽象要求。
3. **先写六到八条写法，每条配一个例句。** 只写「不要什么」，模型知道该避开什么，却不知道往哪走。
4. **禁用词表从你最受不了的 AI 腔开始**，十几个就够，以后再加。

## 日常循环

```
写稿 → 作者反馈或亲手改 → 记进 feedback-log → 同一规律出现两次 → 写进 profile → CHANGELOG 记一行
```

- 每次反馈都记，不用问。记的时候写原话或改动对照，再写你看出的规律。规律是推测，原话是证据，分开写。
- 作者认可的稿子、作者自己写的文字，存进 `voice/samples/`。
- 作者说「以后都这样」的，一次就能进 profile。只出现过一次的，先留在日志里。

## 证据分轻重

从重到轻排，作者原文，亲改对照，作者口头反馈，作者认可的 AI 稿，AI 自己的推测。

认可稿有个陷阱。它是 AI 理解的你，模型最容易照着一整篇范文学，学多了风格就会被拉向 AI 心目中的克制，平稳，正确，没有你自己的毛边。所以认可稿可以用，原文要尽快攒。

## 什么时候归纳

日志攒到五条左右，或者大约一个月，或者作者说「归纳一下」。归纳时做这几件事。

1. 把日志里重复出现的规律合并，写进 profile，每条配例句。
2. 跟新证据冲突的旧规则，改掉或删掉。
3. 看 profile 有没有超过一页。超了就合并，规则越多，模型越拘谨。
4. 新加的禁用词同步进 `checks.txt`。
5. 在 CHANGELOG 记版本号、日期和改了什么，告诉作者。

## 这份 Skill 踩过的坑

- **规则越写越多，越写越谨慎。** v0.4 时写作要读的文件里塞满了出处说明和免责声明，比如「不标为作者原创」「规则检查通过不代表作者认可」。模型读多了，写出来也变得四平八稳、处处保留。v0.5 把证据全挪到 `evolution/`，profile 只留能指导下笔的内容。
- **几乎全是「不要」。** 改成每条写法配正面例句。
- **两份正面证据互相打架。** 访谈时认可的是带括号、岔话和「卧槽」的活泼语气，唯一的整篇范本却是一篇平稳克制的认可稿。用脚本查那篇范本，括号零处，情绪词零处，二十一个句子长度几乎一样。模型会跟着整篇范文走，把活泼的那部分丢掉。解决办法是分语气档位，写自己的项目用放开档，评论别人用平实档。
- **硬规则靠模型记会漏。** 冒号、破折号、「我觉得」，改着改着就回来了。交给脚本查。
- **跟别的写作 Skill 抢触发词。** 装了别人的风格 Skill 以后，「按我的风格写」可能被它接走，写出来署的是别人的名。个人写作只留一个 Skill。

## 想做自己版本的话

1. 复制整个目录，改 SKILL.md 里的名字和 description。
2. 清空 `voice/samples/` 和 `evolution/feedback-log.md`，CHANGELOG 从 v0.1 开始。
3. 照上面的冷启动做一遍，重写 `voice/profile.md` 和 `voice/checks.txt`。
4. 之后每次用都让它记反馈，攒够了就归纳。前几周会改得很勤，一两个月后会慢慢稳定。
